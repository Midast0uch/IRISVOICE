## Session 290 — follow-up testing + two fixes
- Verified session 289's TTS/audio fixes with the project's own tests: `contract/test_tts_subprocess_contract.py` + `behavioral/test_tts_event_loop.py` = 12 passed.
- **Pre-existing failures (NOT regressions, verified identical on pristine HEAD via `git checkout`)**:

  - `unit/test_tool_decision.py::TestResolveFail::test_unparseable_json`.
  - Back up modified files to a temp dir, `git checkout --` them, run, then restore — never assume a failure is pre-existing.
- **Defect found in session 289's own `_put_chunk` fix**: it retried `queue.put` on a 0.25s cycle but exited ONLY on `interrupted`/`is_speech_interrupted`. The consumer's two timeout paths (60s pre-first-audio, 0.5s post-streaming) `break` WITHOUT setting `interrupted`, so a producer would spin forever holding the process-wide `TTSManager._synthesis_lock`. Fixed by bounding *unbroken* queue fullness to 5s (`_PUT_STALL_LIMIT`).
- **Root cause of the `ask_user_question` loop**: `reset_failure_counters()` is called by the DER on every `_split_step`, wiping `_tool_fails`. So the per-tool failure budget of 3 could never contain a call that fails across splits. The duplicate/loop detector is also success-gated (only counts repeats of *successful* calls), so repeated identical failures never trip it. Fixed with a `self._permanent_failed_args` tally (tool+args_hash -> count) that is deliberately NOT cleared on reset, firing *after* the budget check so the budget's "exceeded" message still wins within a box. Threshold 3 = same as the budget. Proven: pristine re-dispatched 6/6 times; fixed stops after 3.
- **Contract constraint — do not widen**: `contract/test_brain_tool_handshake.py::test_same_model_means_no_handshake_and_no_extra_call` passes an INCOMPLETE `ask_user_question` call and asserts same-model returns it untouched with zero extra model calls. So the repair can never be moved into `_complete_params_via_brain` for the same-model path; it must stay a dispatch-boundary guard.
- `_classify_error()` returns "permanent" for any error string it doesn't recognise — a tool returning `{"success": False, "error": "transient blip"}` with no explicit `error_type` is classified PERMANENT. Any new anti-loop logic at dispatch must not preempt the failure budget or it will break `unit/tool_safety_test.py::TestPerToolBudget`.

## Prism cards drifting to the bottom of the scroll (frontend)
- User requirement: **plain text and a render must be able to coexist in one response**, and a card must stay with its turn.
- Architecture in `components/chat-view.tsx` is already right: cards join INLINE on `doc.turnId === message.id` (~line 4030). The bottom-stacked block (~4190) is only an ORPHAN fallback for docs whose `turnId` matches no message — a hydration safety net.
- ROOT CAUSE of the drift: two ingest sites suppressed the assistant text whenever ANY document existed for the turn — `activeDocTurnIdsRef.current.has(turnId)` in the WS `iris:text_response` handler (~1045) and in the REST `/api/chat` `.then()` (~2080). Because the message was never created, **no message carried `id === turnId`**, so the inline join never matched and every prism card fell through to the orphan block. Same bug also swallowed the narration the user should read beside the card.
- FIX: added `activeDocContentsRef` (turnId -> normalized doc content), module-level `normalizeCardText()`, and `isTextRenderedAsDocument()`. Both suppression sites now skip the text ONLY when a document for that turn already renders that exact text — so a card merely existing no longer eats the answer, and the turn keeps a message for the card to attach to.
- Streaming note: `iris:chat_chunk` creates its message with `id: turnId`, so a turn that streamed text before the card arrived already matched inline. Turns with NO streamed chunk were the ones that orphaned.
- Committed as `3b09f929` (`fix: keep prism cards inline with assistant turns`). Post-commit MCM edit/test events and a pin were recorded for the six changed files and verification outcomes. The working tree still contains unrelated pre-existing staged/untracked artifacts; they were not included in the commit.
