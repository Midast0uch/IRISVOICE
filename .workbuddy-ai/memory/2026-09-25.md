## Model-swap candidate: GLiNER2.5-Decide (user is considering replacing LFM2-350M)

Source: https://huggingface.co/fastino/GLiNER2.5-Decide (fastino, Apache 2.0)

**What it is:** 340M **encoder-only** classifier on a **DeBERTa-v3-large** backbone. You pass
raw text + a *schema* of named heads (label lists / described labels / multi-label / yes-no),
and it returns the selected label(s) plus per-label scores. Explicitly: **"no prompt
template, no generated tokens, exactly one forward pass"**, and **one call scores several
heads at once**. `gliner2` library via `AutoExtractor`, CPU or GPU.

**Why it's interesting — it natively implements all three JEV primitives:**
- Choice → intent/routing label sets
- Score → ordinal scales (priority/urgency/severity, "0"–"10")
- Noul → yes/no heads (human-handoff gate, "did the agent finish?", question-over-passage)

**Benchmark (fast-decisions, 17 domains, English, exact-match):** GLiNER2.5-Decide 340M =
**60.2%**, beating **JevK5 57.6%** and **Laya Router 46.6%** (Laya = the hosted router the
spec already rejected), and beating a 4B model (SemIf/Qwen3.5-4B 56.4%).

**NOT stated on the model card (must be measured):** latency, weight size, ONNX/GGUF/
llama.cpp support, exact head mechanism (label logits vs span scores), transformers support.

**Implications if adopted:**
- Satisfies the spec's REQ-20 gap (parallel multi-question) natively — no batching to build.
- Removes the whole LFM2 logit-hacking stack: REQ-1 (letter/first-token scoring) becomes moot,
  and the `softmax_tau` calibration problem (REQ-18) disappears.
- Removes the need for REQ-19 (per-consumer prompt heads) — replaced by schema heads.
- **But:** it CANNOT generate tool args, so `generate_args` still needs a generative model or
  deterministic arg filling. REQ-2 survives in some form.
- **But:** encoder-only ⇒ the T23 "warm head KV snapshot" optimization is meaningless
  (no autoregressive prompt prefill at all). Latency profile changes entirely.
- **But:** deployment is PyTorch/`gliner2`, not llama.cpp — check CT-DEI-1 (zero VRAM ledger,
  CPU-resident) still holds, and whether torch is already a dependency in the backend venv.
- **Decision Lock impact:** the spec's "Native LFM2-350M-Extract Retention" lock would need
  explicit revision. Note it is NOT a hosted cloud router, so it does not violate the
  "no external hosted dependency" rule — only the literal model-retention lock.
- **Recommended path:** extend T0 into a 3-way probe (letters vs first-token vs
  GLiNER2.5-Decide) on `scripts/fixtures/decision_engine_cases.json`, measuring accuracy,
  coverage at 0.85, and p50 CPU latency. Do NOT swap blind — latency is unmeasured.

calibration rows were generated through the worse path.
