# debugging
- When diagnosing a bug from code inspection alone, qualify the confidence of the diagnosis and offer to run empirical tests (e.g., measuring actual RMS levels, adding logging, reproducing) before asserting the root cause as settled. Confidence: 0.65
- Don't blame a component for a bug without establishing a causal chain — if logs show `is_recording=False` but the symptom is "transcript not processed," verify that the blamed component (e.g., wake-word config) can actually cause the observed symptom before pinning the diagnosis on it. Confidence: 0.65
- When fixing a parameter-propagation or regression bug, trace the entire call chain end-to-end before declaring the fix complete — don't fix just the one discovered instance and stop, as there may be additional missing propagation points downstream. Confidence: 0.75
- Do not paper over missing dynamic values with hardcoded constants — if an attribute like `confidence` is supposed to come from a task classifier or memory system, fix the actual data flow rather than substituting a literal. Confidence: 0.70
- When finding a hardcoded model name that causes a cryptic 404 (e.g., `command-a-03-2025`), replace it with a clear RuntimeError saying "No reasoning model configured" instead of silently failing. Confidence: 0.70
- When debugging a WS-driven UI state bug (e.g., orb not animating on wake word), verify each layer of the chain in order — backend routing, WS message delivery, frontend handler, context provider, component subscription — to systematically isolate the failure layer before declaring the root cause. Confidence: 0.70
- When diagnosing a live WS routing issue where the backend control path is blocked by hardware/external dependencies, write a simulation that exercises the real backend code paths (not mocks of the path under test) to prove backend correctness and isolate whether the bug is backend or frontend. Confidence: 0.68
- Do not settle for symptom-level fixes when the symptom reveals a deeper architectural root cause — even if the symptom-level patch would resolve the immediate error, address the architectural root cause instead, as the user explicitly rejects band-aid fixes. Confidence: 0.65
- When the orb's "listening" visual is gated solely on `breathLevel > 0`, a silent mic (VAD discarded buffer, wrong input device) makes listening look identical to idle — decouple the sustained "I'm recording" visual from audio energy by using `isBreathing`/`glowActive` as the primary gate with a minimum floor, so the listening state is always visibly distinct from idle. Confidence: 0.78
